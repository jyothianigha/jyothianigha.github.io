JAVA — CLASS-LEVEL MEMBERS

Static Members in Java

Most of a class's fields and methods belong to each object separately. Mark one static, and it belongs to the class itself instead — one shared copy, no matter how many objects you create.

03

Static Variables

Also called class variables. Because there's only one copy, changing it through any object — or through the class name directly — changes it for everyone.

Account.java
class Account {
    static double interestRate = 0.05;  // shared by every Account
    double balance;
}

Account a = new Account();
Account b = new Account();

Account.interestRate = 0.07;   // change it once...
// ...and a.interestRate and b.interestRate are BOTH 0.07 now
04

Static Methods

A static method belongs to the class too, which means it runs without any object ever existing — and, crucially, it has no this to work with.

MathUtils.java
class MathUtils {
    static int square(int n) {
        return n * n;
    }
}

int r = MathUtils.square(5);
// no "new MathUtils()" needed
Broken.java
class Broken {
    int x = 10;           // instance field

    static void show() {
        System.out.println(x);
        // ✕ compile error:
        // no object → no x to read
    }
}
Rule of thumb

A static method can only reach other static members directly. To touch an instance field or call an instance method, it needs an actual object reference to do it through — the same way any outside code would.

05

Static Initialization Blocks

For setup too involved for a one-line field initializer. A static block runs exactly once — the moment the class is first loaded, before main or any constructor runs.

Config.java
class Config {
    static Map<String, String> settings;

    static {                          // runs once, at class-load time
        settings = new HashMap<>();
        settings.put("env", "production");
    }
}
